# Security Policy

## Secret-Management Policy

- All secrets (broker credentials, API tokens, notification tokens) are
  supplied exclusively via environment variables, loaded from a local `.env`
  file that is **never** committed to Git.
- `.env.example` contains placeholder variable names only — never real or
  realistic-looking secret values.
- No secret may appear in source code, configuration files committed to
  Git, commit messages, documentation, logs, or test fixtures.
- No secret may ever be requested from, generated by, or entered into this
  repository by an AI coding assistant on the user's behalf — the user
  manages actual secret values themselves.

## GitHub Private Repository Expectations

- This repository is expected to be hosted as a **private** GitHub
  repository. Never take any action that would make it public.
- Branch protection on `main` is expected once a remote is configured
  (no direct pushes, PR review required) — this is a repository-settings
  concern, not something committed into the codebase.
- No repository secret, deploy key, or access token is to be printed,
  logged, or embedded in workflow files in plaintext; GitHub Actions
  secrets must be referenced via `${{ secrets.NAME }}` only, when such
  secrets are introduced in a later phase.

## `.env` Usage

- Copy `.env.example` to `.env` locally and fill in real values there.
- `.env` is listed in `.gitignore` and must never be staged or committed.
- Different environments (research, demo, live) should use distinct `.env`
  files or distinct secret values — never share live credentials with a
  research/demo setup.

## Credential Rotation

- Broker and API credentials should be rotated periodically and
  immediately after any suspected exposure (e.g., accidental commit, shared
  screen, leaked log).
- Rotation events should be noted (without secret values) in the project's
  incident log once operational tooling exists (Phase 7+).

## Log Redaction

- Structured logging (Phase 7+) must redact or omit credential values,
  account numbers, and tokens by construction — logging code must never
  format raw environment variable values that could contain secrets.
- Log review before sharing logs (e.g., for debugging help) is required to
  confirm no sensitive data is present.

## Broker Account Safety

- Broker account numbers and passwords must never be committed, logged, or
  hardcoded.
- Live-account credentials must be kept separate from demo-account
  credentials, both in storage (`.env` values) and in configuration
  (explicit environment selection, not inferred).
- No code path may default to a live account when a mode is unspecified —
  ambiguity must fail safe (i.e., must not trade).

## Telegram Token Safety

- Telegram bot tokens and chat IDs (used for alerting, Phase 7+) follow the
  same rules as broker credentials: environment variables only, never
  committed, never logged.
- A leaked Telegram bot token must be rotated immediately via BotFather, as
  it grants control of the bot.

## Prohibition Against Committing Account Numbers and Passwords

Committing any of the following to this repository, in any form (code,
config, comment, doc, commit message, test fixture) is strictly prohibited:

- Broker login/account numbers
- Broker passwords or investor passwords
- API keys or tokens of any kind
- `.env` files with real values

## Incident-Response Procedure

If a secret is accidentally committed or exposed:

1. Treat the credential as compromised immediately.
2. Rotate/revoke the credential at its source (broker, Telegram, etc.)
   before doing anything else.
3. Remove the secret from the current file(s) in a new commit.
4. Note that Git history rewriting (to purge the secret from history) is a
   destructive operation and must be explicitly approved by the project
   owner before being performed — do not force-push or rewrite history
   unilaterally.
5. Record the incident (what leaked, when, remediation taken) once an
   incident log exists (Phase 7+).

## Pre-Push Security Checklist

Before pushing any commit:

- [ ] No `.env` file is staged.
- [ ] No credential, token, password, or account number appears in the
      diff.
- [ ] No new file under `data/`, `state/`, `reports/`, or log output is
      staged.
- [ ] `.gitignore` still covers all secret and runtime-state paths.
- [ ] CI (lint, type-check, tests) passes locally before pushing.
- [ ] The diff contains no unrelated changes beyond the task's scope.
